# Метрики Пилота

## Зачем Нужны Метрики

AI-Бухгалтер должен доказывать ценность не обещаниями, а измеримыми
результатами. Для пилота важнее показать, где система реально экономит время и
снижает хаос, чем заявлять абстрактную "автоматизацию бухгалтерии".

## Основные Метрики

| Метрика | Что Показывает |
| --- | --- |
| Время обработки документа | ускоряется ли первичная обработка |
| Время сверки операции | меньше ли ручного поиска |
| OCR acceptance rate | доля полей, принятых без исправлений |
| Reconciliation acceptance rate | доля принятых совпадений |
| Количество расхождений | сколько проблем найдено до закрытия периода |
| Missing documents | сколько недостающих документов выявлено |
| Overdue tasks | качество контроля сроков |
| Client response time | скорость закрытия вопросов с клиентом |
| AI rejection rate | где AI ошибается или не помогает |
| Cost per document | экономика OCR/LLM на единицу обработки |
| Clients per accountant | влияние на операционную мощность команды |

## Pilot Dashboard

Целевой pilot dashboard должен отвечать на вопросы:

- сколько документов обработано;
- сколько полей исправлено человеком;
- какие классы ошибок самые частые;
- сколько AI-предложений принято;
- где бухгалтерам пришлось вмешиваться;
- какие клиенты создают больше всего ручной работы;
- сколько стоит обработка одного клиента.

## Без Фиктивных Обещаний

В публичном репозитории не указываются выдуманные проценты эффективности.
Корректная позиция:

- определить метрики;
- запустить пилот;
- собрать baseline;
- сравнить ручной и AI-assisted процесс;
- публиковать только проверенные результаты.
